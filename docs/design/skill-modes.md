# 스킬 호출 방식 관리 설계

대시보드에서 코딩 에이전트별로 스킬의 호출 방식(자동 · /명시 전용 · 꺼짐)을 정한다.

- 전역 기본값을 한꺼번에 정하고, 프로젝트마다 예외를 둔다.
- 프로젝트 예외는 "나만"(내 PC)과 "팀 공유"(저장소에 커밋) 중 고른다.
- 한 스킬을 모든 에이전트에서 한 번에 바꾸는 보기도 둔다.

화면 시안: [skill-modes-prototype.html](skill-modes-prototype.html). 브라우저로 열면 바로 눌러 볼 수 있고, 데이터는
예시다.

- 상태: 1~3단계 구현 (2026-09-30). 4단계는 CodeBuddy 수집만 했다. 구현하며 바꾼 점은 9장.
- 범위: `kit/user/skill-stats.mjs`(서버), `skill-dashboard.html`(화면), `skill-policy.mjs`(세션 시작 점검),
  `skill-sets.mjs`(`skills on/off` 명령), `policy.json`(형식 변경)
- 하지 않는 것: 스킬 설치·삭제, 플러그인 안의 스킬 하나씩 제어

## 1. 조사 결과: 에이전트마다 호출 방식을 바꾸는 방법

이 PC에 설치된 실행 파일과 공식 문서로 확인했다. "미확인"은 로그인한 실제 세션으로 시험해야 한다.

| 에이전트 | 전역 | 프로젝트 · 팀 공유 | 프로젝트 · 나만 | 고를 수 있는 값 | 키 |
| --- | --- | --- | --- | --- | --- |
| Claude Code | `~/.claude/settings.json` `skillOverrides` | `.claude/settings.json` | `.claude/settings.local.json` | 자동·명시 전용·꺼짐 | 이름 |
| CodeBuddy Code | `~/.codebuddy/settings.json` `skillOverrides` | `.codebuddy/settings.json` | `.codebuddy/settings.local.json` | 같음 | 이름 |
| Qwen Code | `~/.qwen/settings.json` | `.qwen/settings.json` | 없음 | 자동·꺼짐 | 이름 |
| Codex | `~/.codex/config.toml` `[[skills.config]]` | `.codex/config.toml` (**미확인**) | 없음 | 자동·꺼짐 | 이름 또는 경로 |
| ZCode | `~/.zcode/cli/config.json` `skillOverrides` | `.zcode/config.json` | 없음 | 자동·꺼짐 | 경로 |
| Kimi Code (앱) | 없음 | 없음 | 없음 | 바꿀 수 없음 | – |

- **우선순위**: 나만 > 팀 공유 > 전역.
  - Claude Code와 CodeBuddy는 이 순서로 스킬 이름마다 따로 합친다(두 도구 실행 파일에서 확인).
  - 나머지는 프로젝트 파일 하나뿐이다. 그 파일을 git에 올리면 팀 공유, 안 올리면 사실상 나만이다.
- **`/skills` 화면이 쓰는 곳**: Claude Code, CodeBuddy, Qwen Code 모두 프로젝트 파일에 쓴다. Qwen은 워크스페이스
  설정이다. 대시보드의 프로젝트 예외와 같은 곳이다.
- **Qwen Code의 세 가지 키**(실행 파일에서 확인):
  - `skills.disabled`: 강제로 끔. 다른 설정으로 되살릴 수 없다.
  - `skills.defaultDisabled`: 기본만 끔.
  - `skills.enabled`: `defaultDisabled`를 되살린다.
  - 그래서 전역 꺼짐은 `defaultDisabled`로 쓴다. 그래야 프로젝트에서 `enabled`로 예외를 둘 수 있다.
  - 명시 전용은 SKILL.md 앞머리(`disable-model-invocation`)로만 되고, 화면에 "Manual reference"로 보인다.
- **명시 전용을 설정으로 못 하는 에이전트**(Codex, ZCode, Qwen Code, Kimi Code): 스킬 폴더 안의 파일을 고쳐야
  한다. 업데이트하면 사라지므로 대시보드는 하지 않고, 흐리게 한 뒤 이유를 보여 준다.
- **이름 키와 경로 키**: 이름 키는 같은 이름의 사본을 모두 바꾸고, 경로 키는 사본 하나만 바꾼다. 경로 키는 Codex
  중복 등록 정리에 쓴다.
- **공유 폴더**: `~/.agents/skills`는 Codex, Kimi Code, ZCode가 함께 읽는다. 한 곳에 설치하면 세 에이전트의
  요청마다 비용에 들어간다.
- **설치된 도구 상태 (2026-09-30)**

| 도구 | 설치 | 기록 위치 | 로그인 |
| --- | --- | --- | --- |
| Qwen Code 0.24.7 | `%LOCALAPPDATA%\qwen-code` (단독 설치본, npm 아님) | `~/.qwen/projects/<폴더>/chats/<세션>.jsonl` | 안 됨 (`No auth type is selected`) |
| CodeBuddy Code 2.159 | npm | `~/.codebuddy/projects/<폴더>/<세션>.jsonl` | 안 됨 (`Authentication required`) |
| Kimi Code (앱) | 데스크톱 앱 | `~/.kimi-code/sessions/…` | 앱을 아직 안 켬 |
| ZCode (앱) | 데스크톱 앱 | `~/.zcode` (세션은 SQLite로 보임) | 앱을 아직 안 켬 |

"Qwen" 데스크톱 앱은 채팅 앱이라 Qwen Code와 별개다.

- **Claude Code에서 모델만 바꿔 쓰는 경우**(GLM, Kimi K2, DeepSeek 등): 기록에 그 모델 이름이 남아 수집은 지금
  그대로 된다. 모델별로 나눠 보는 보기를 덧붙인다.

## 2. 대시보드 값과 policy.json: 기준값을 하나로

### 지금 구조의 문제

지금은 세 곳이 값을 들고 있다.

| 파일 | 들고 있는 값 | 누가 쓰나 |
| --- | --- | --- |
| `policy.json` | `manualSkills`(명시 전용), `offSkills`(끄고 폴더도 지움) | 사람이 직접 |
| `state.json` | `disabled` (`skills off`로 끈 것) | `skills off` 명령 |
| `settings.json` | `skillOverrides` (Claude Code가 실제로 읽는 값) | 위 둘을 적용한 결과, `/skills`, 업그레이드 |

세션 시작 훅은 앞의 둘을 합쳐 기대값을 만들고, 셋째와 다르면 되돌리자고 묻는다. 여기에 대시보드가 `settings.json`만
바꾸면 다음 세션에 "되돌릴까요?"가 나온다. 사용자는 셋 중 무엇이 맞는지 헷갈린다.

### 결정

1. **내 값의 기준은 `policy.json` 하나다.**
   - 대시보드, `skills on/off` 명령, 훅의 "지금 값 채택"이 모두 여기에 쓴다.
   - `state.json`에는 설치 기록만 남긴다.
2. **에이전트 설정 파일은 적용값이다.** 대시보드는 기준값과 적용값을 한 번에 바꾸므로, 대시보드 때문에 둘이
   달라지지 않는다.
3. **차이는 밖에서만 생긴다.** 업그레이드, `/skills` 화면, Codex 앱, 손으로 고친 경우다. 이때 "기준값과 다름"으로
   표시하고 두 방향을 모두 준다.
   - **기준값대로 되돌리기**: 적용값을 기준값으로 덮는다.
   - **지금 값 채택**: 적용값을 기준값으로 가져온다.
4. **기준값에 없는 스킬은 건드리지 않는다.** 적용값만 보여 준다(관리 안 함). 대시보드에서 값을 정하는 순간 관리
   대상이 된다.
5. **꺼짐과 폴더 삭제를 나눈다.** 꺼짐은 숨기기만 한다. "다시 설치되면 폴더 삭제"는 `removeIfReinstalled`로 옮긴다.
6. **팀 공유 값은 policy.json에 넣지 않는다.**
   - 팀 파일(`.claude/settings.json` 등)의 기준은 저장소의 git 기록이다.
   - 동료가 바꾼 값이 git pull로 들어올 때마다 "기준값과 다름"이 뜨면 안 되기 때문이다.
   - 대시보드는 팀 파일을 직접 고치고, 대신 "커밋 안 됨" 상태를 보여 준다(3장).

화면에서는 파일 이름 대신 "기준값"과 "적용값"이라는 말만 쓰고, 미리보기에서만 실제 파일 경로를 보여 준다.

### policy.json v2 형식

```json
{
  "version": 2,
  "modes": {
    "claude": {
      "global": { "review": "manual", "qa": "manual", "autoplan": "off", "html": "auto" },
      "projects": { "E:/Project/Travino": { "review": "off" } }
    },
    "codex": { "global": { "path:C:/Users/me/.codex/skills/gstack/autoplan": "off" }, "projects": {} },
    "qwen": { "global": {}, "projects": {} }
  },
  "removeIfReinstalled": ["autoplan"],
  "localOnlySkills": ["browseros-neo", "neo-naver-blog"],
  "localSkillProjects": [],
  "stripSuperpowersBootstrap": true,
  "userPlugins": { "enable": {}, "disable": ["expo@claude-plugins-official"] },
  "projectPluginRemovals": {}
}
```

- 값은 `auto` · `manual` · `off`. `projects`에는 "나만" 예외만 들어가고, 키가 없으면 따름이다.
- 전역의 `auto`는 "덮어쓰는 값이 없어야 한다"는 뜻이다. 업그레이드가 끄면 차이로 잡힌다.
- 경로로 지정할 때는 키 앞에 `path:`를 붙인다.
- **v1에서 옮기기**: v1을 읽으면 자동으로 옮기고, 원본은 `policy.v1.json`으로 남긴다.
  - `manualSkills` → `manual`
  - `offSkills` → `off`, 그리고 `removeIfReinstalled`
  - `state.json`의 `disabled` → `off`

### 템플릿 권장값이란

이 저장소의 `kit/user/policy.json`은 팀이 권하는 기본 설정이다(예: gstack 스킬은 명시 전용).

- `node setup.mjs user`를 처음 실행할 때 이것이 `~/.claude/skill-policy/policy.json`으로 한 번 복사된다.
- 그 뒤로는 다시 덮어쓰지 않는다. 대시보드에서 바꾸는 것은 내 사본이다.
- 그래서 나중에 팀이 권장값을 바꿔도(예: 새 스킬을 명시 전용 목록에 추가하고 git pull) 내 사본에는 들어오지 않는다.
- "권장값과 비교"는 이 차이를 보여 주고 새 권장값을 골라서 가져오는 기능이다.
- **결정**: 이번 범위에서는 넣지 않는다.
  - 팀 공유 설정 쓰기가 생기면서, 프로젝트에 필요한 값은 저장소의 팀 파일로 바로 공유된다.
  - 그러면 권장값은 전역 기본값의 첫 설정 용도만 남는다.
  - 필요해지면 "전역 기본값" 열 머리에 "권장값과 다른 N개 · 가져오기"를 덧붙인다.

## 3. 적용 규칙

실제로 쓰이는 값은 다음 순서로 정해진다.
1. 나만
2. 팀 공유
3. 전역 기본값
4. 스킬 기본값: 보통 자동이고, SKILL.md가 명시 전용이면 명시 전용

| 에이전트 | 전역 자동 | 전역 명시 전용 | 전역 꺼짐 | 프로젝트 예외 (팀·나만) | 따름(예외 지우기) |
| --- | --- | --- | --- | --- | --- |
| Claude Code, CodeBuddy | 키 삭제 | `user-invocable-only` | `off` | `on` · `user-invocable-only` · `off` | 키 삭제 |
| Qwen Code | 목록에서 빼기 | (지원 안 함) | `skills.defaultDisabled`에 넣기 | 꺼짐: `defaultDisabled`, 자동: `enabled` | 목록에서 빼기 |
| Codex | 블록 삭제 | (지원 안 함) | `[[skills.config]] enabled = false` | `.codex/config.toml` (시험 뒤 켬) | 블록 삭제 |
| ZCode | 키 삭제 | (지원 안 함) | `{ "enable": false }` | `enable: true/false` | 키 삭제 |

잠금(고를 수 없는 값)과 그 이유를 칸마다 보여 준다.

- 플러그인 스킬: 플러그인 켜기·끄기로 안내한다.
- SKILL.md에 `disable-model-invocation: true`: 자동을 고를 수 없다.
- 관리자 정책 설정(`policySettings`)에 값이 있으면 바꿀 수 없다.
- 에이전트가 지원하지 않는 값: Codex·ZCode·Qwen의 명시 전용, Kimi Code 전체.
- Qwen의 `skills.disabled`(강제 끔)에 있는 스킬: 프로젝트에서 되살릴 수 없다.

### 팀 공유 쓰기

- **팀 파일은 저장소에 커밋해야 동료에게 간다.** 적용 뒤 "팀 파일 N개가 바뀌었습니다 · 커밋해야 공유됩니다"와
  바뀐 파일 목록을 보여 준다. 대시보드가 커밋하지는 않는다.
- **팀 값을 바꿔도 내 "나만" 값이 있으면 나에게는 내 값이 이긴다.** 칸 메뉴에 "나만 값 때문에 이 PC에서는 X로
  보입니다"를 적는다.
- **팀 파일이 git 작업 트리에 아직 커밋 안 된 변경을 갖고 있으면** 칸에 "커밋 안 됨" 표시를 단다.
- 팀 파일에는 설정 파일의 다른 키(권한, 훅 등)가 함께 있다. 대시보드는 `skillOverrides` 같은 스킬 키만 고치고
  나머지는 그대로 둔다.

## 4. 화면 설계

지금 대시보드의 모양과 부품을 그대로 쓴다. 위쪽 막대, 요약 카드, 패널, 분류별 묶음, 막대 칸, 점 색이 그 부품이다.
새 부품은 호출 방식 선택 하나뿐이다.

### 에이전트 색

- 에이전트가 여섯 개를 넘으면 자동(호박색) · 명시 전용(청록) · 경고(빨강)와 겹치지 않으면서 서로 구분되는 색이
  모자란다. 색 검증기로 확인했고, 회색 계열은 "색으로 안 읽힘"으로 탈락했다.
- 그래서 검증한 네 칸만 색을 쓴다: Claude Code 파랑, Codex 마젠타, CodeBuddy 보라, Qwen Code 초록.
- 나머지(ZCode, Kimi Code, Gemini CLI, Copilot CLI)는 두 글자 이름 배지(`ZC`, `KM` …)로 구분한다.
- 이름은 늘 같이 보여 주므로 색만으로 구분하지 않는다.
- 현황판의 에이전트별 누적 차트는 색이 있는 넷과 "기타"로 접는다. 지금 현황판에서 Gemini CLI와 Copilot CLI에 준 색은
  구현 때 이 규칙으로 바꾼다.

### 위치

위쪽 메뉴를 **현황판 · 호출 방식 · 사용법**으로 늘린다. 현황판에서 스킬 행의 호출 방식 칸을 누르면 이 페이지의
그 스킬로 간다.

### 요약 카드 (현황판과 같은 모양)

| 카드 | 내용 |
| --- | --- |
| 요청마다 고정 비용 | 지금 → 적용 뒤 (에이전트별) |
| 적용 대기 | 대기 중인 변경 수, 바뀌는 파일 수 |
| 기준값과 다름 | 밖에서 바뀐 설정 수 · 모두 되돌리기 / 채택 |
| 프로젝트 예외 | 나만 · 팀 공유 예외 수, 커밋 안 된 팀 파일 수 |

### 보기 두 가지

위쪽에 [에이전트별] [스킬별 · 모든 에이전트] 전환을 둔다.

**에이전트별**: 한 에이전트 안에서 전역과 프로젝트를 한꺼번에 다룬다.

```
에이전트: [● Claude Code] [● Codex] [● CodeBuddy] [● Qwen Code] [● ZCode] [● Kimi Code 🔒]
▾ 리뷰·보안·품질  4개 · 요청마다 159            [이 묶음 전체 ▾]
☐ review   gstack      [ 자동 | 명시 전용 | 꺼짐 ]   my-app ○꺼짐 (나만)  api-server ● 팀
☐ qa       gstack      [ 자동 | 명시 전용 | 꺼짐 ]  ⚠ 기준값과 다름
▸ 테스트·브라우저  6개
```

- **행은 현황판처럼 분류별로 묶는다.** 묶음 머리의 "이 묶음 전체 ▾"로 묶음 단위 일괄 변경을 한다.
- **전역 값은 행마다 3칸 선택 단추로 바로 바꾼다.** 한 번 누르면 된다. 가장 자주 하는 일이라 메뉴를 열지 않는다.
- **프로젝트는 표의 열로 늘어놓지 않는다.** 예외가 있는 프로젝트만 행에 칩으로 보여 준다.
  - 예: `my-app ○ 꺼짐 · 나만`, `api-server ● 명시 전용 · 팀`.
  - 앞 시안처럼 전역을 따르는 칸이 "↳ 명시 전용"으로 반복되는 소음이 없어져서, 예외가 눈에 띈다.
- **칩이나 "+ 예외"를 누르면 작은 창이 뜬다.** 프로젝트를 고르고, 층(나만 / 팀 공유)을 고르고, 값을 고른다.
  - 칩을 누르면 해당 프로젝트와 층이 미리 골라져 있다.
  - 지원하지 않는 값은 흐리게 하고 이유를 적는다.
- **범위 거르기**: 위쪽 [모든 프로젝트 ▾]에서 프로젝트 하나를 고르면, 각 행에 그 프로젝트의 실제 값이 함께
  보인다. `/skills` 화면처럼 한 프로젝트 기준으로 보는 방법이다.

**스킬별 · 모든 에이전트**: 한 스킬을 모든 에이전트에서 한 번에 바꾼다.

```
☐ 스킬           Claude Code   Codex        CodeBuddy   Qwen Code   ZCode      Kimi Code
☐ grilling      ● 자동         ● 자동        ● 자동       ● 자동       ● 자동      🔒 자동
☐ html          ● 자동         ● 자동 (×2)   —           —           ● 자동      🔒 자동
  [선택 2개를 모든 에이전트에서 → 명시 전용]  명시 전용을 못 하는 에이전트: (○ 건너뜀  ● 꺼짐으로)
```

- 행은 스킬 이름이고, 열은 에이전트다. 칸은 각 에이전트의 전역 값이며, 그 에이전트에 없는 스킬은 "—"다.
- 칸을 누르면 그 에이전트 하나만 바꾸고, 행 끝 단추를 누르면 모든 에이전트를 바꾼다.
- 명시 전용을 지원하지 않는 에이전트가 섞이면 "건너뜀 / 꺼짐으로" 중에 고르게 한다. 조용히 다른 값을 넣지 않는다.
- 공유 폴더 스킬(`~/.agents/skills`)에는 "공유 폴더" 표시를 단다.

### 일괄 조작 (가장 먼저)

- 행을 체크하고 Shift+클릭으로 범위를 고른다. 묶음 머리와 필터 결과 전체에도 선택 상자를 둔다.
- 선택하면 아래에 막대가 붙는다: [범위: 전역 / 프로젝트 ▾ / 나만·팀] [자동] [명시 전용] [꺼짐] [따름].
- 추천 묶음은 한 번에 누른다.
  - 정리 후보 → 명시 전용
  - 중복 사본 끄기
  - 기준값과 다름 되돌리기
  - 누르기 전에 바뀌는 수와 줄어드는 토큰을 보여 준다.

### 모아서 적용

- 바꾼 것은 오른쪽 **변경 목록** 패널에 쌓인다(휴대폰에서는 아래에서 올라오는 창).
  - 항목마다 "스킬 · 범위 · 이전 → 이후"와 개별 취소가 있다.
  - 위에는 요청마다 토큰의 변화가 나온다.
- **미리보기**: 파일별로 "이전 → 이후"를 보여 준다. 기준값 파일, 내 설정 파일, 팀 파일(커밋 필요 표시)로 나눈다.
- **적용**: 백업을 남기고 쓴다. "되돌리기"와 "팀 파일 커밋 필요" 안내를 띄운다.

### 상태

| 상태 | 보이는 것 |
| --- | --- |
| 불러오는 중 | 표 자리에 뼈대, 요약 카드는 "…" |
| 빈 상태 | "이 에이전트에 스킬이 없습니다" + 설치 폴더 안내 (CodeBuddy·Qwen 지금 상태) |
| 보기 전용 | 선택 단추 흐림 + 위에 이유 (Kimi Code) |
| 로그인 안 됨 | 에이전트 탭에 "로그인 필요" (기록은 없고 스킬만 보임) |
| 적용 실패 | 어느 파일에서 실패했는지와 이유, 다른 파일은 되돌림, 다시 시도 |
| 기준값과 다름 | 빨간 테두리 + 위쪽 알림 띠 |
| 커밋 안 됨 | 팀 칩에 점 + 요약 카드 숫자 |

### 키보드와 휴대폰

- Tab으로 행을 옮기고, 선택 단추 안에서는 방향키로 값을 바꾼다. Space로 행을 선택한다.
- 칩 메뉴는 Enter로 열고 Esc로 닫는다. 닫으면 연 칩으로 초점이 돌아간다.
- 휴대폰에서는 행이 카드가 되고, 선택 단추는 전체 폭을 쓴다. 변경 목록은 아래에서 올라오는 창이 된다.

## 5. 서버와 보안

| 요청 | 하는 일 |
| --- | --- |
| `GET /api/modes` | 에이전트별 지원 값·범위, 프로젝트, 스킬마다 기준값·적용값(전역·팀·나만)·잠금·차이·커밋 상태 |
| `POST /api/modes/preview` | 대기 변경 → 파일별 이전·이후 (서버가 계산) |
| `POST /api/modes/apply` | 기준값과 적용값 파일을 함께 쓰고 백업. 하나라도 실패하면 모두 되돌림 |
| `POST /api/modes/undo` | 마지막 적용 되돌리기 |

- **다른 웹사이트가 보낸 요청 막기**
  - 서버를 켤 때 만든 임의 토큰을 페이지에 심고 `X-Skill-Dash-Token` 헤더로만 받는다.
  - `Host`가 `localhost`나 `127.0.0.1`인지 검사한다.
  - JSON만 받는다.
- **파일 경로는 서버가 정한다.** 요청에는 에이전트, 범위, 층, 스킬 이름만 담는다. 스킬 이름은 수집한 목록에 있는
  것만 받는다.
- **쓰기**: 쓰기 직전에 다시 읽는다. 임시 파일에 쓴 뒤 이름을 바꾸고, `.bak`을 남긴다. JSON은 기존 키 순서를
  지킨다. TOML(Codex)은 우리 블록만 더하고 뺀다.
- **git**: 개인 파일을 새로 만들면 `.git/info/exclude`에 넣는다. 팀 파일은 제외하지 않는다.
- **훅(`skill-policy.mjs`)**
  - 모든 에이전트의 관리 대상 키(전역·나만)를 비교한다.
  - 차이가 있으면 "되돌리기 / 지금 값 채택"을 묻는다. `--adopt` 옵션을 더한다. 팀 파일은 비교하지 않는다.

## 9. 구현 메모 (2026-09-30)

- **코드 위치**: 기준값·설정 파일 읽기와 쓰기는 `kit/user/skill-modes.mjs` 하나에 모았다. 서버(`skill-stats.mjs`),
  훅(`skill-policy.mjs`), `skills on/off/manual`(`skill-sets.mjs`)이 같은 쓰기 경로를 쓴다.
- **백업 위치**: 파일 옆 `.bak` 대신 `~/.claude/skill-policy/backups/<시각>/`에 모은다(최근 20번). 팀 파일 옆에
  `.bak`이 생기면 저장소에 커밋 안 된 파일이 늘기 때문이다.
- **되돌리기**: 마지막 적용의 이전·이후 내용을 `modes-undo.json`에 남긴다. 그 뒤에 파일이 다시 바뀌었으면 되돌리지
  않고 어느 파일인지 알린다. `skills on/off/manual`도 같은 기록을 남기므로 대시보드에서 되돌릴 수 있다.
- **Codex 경로 키**: 기준값 키는 `path:<스킬 폴더>`, `config.toml`에는 Codex 형식대로 SKILL.md 경로를 쓴다.
  Codex는 꺼진 스킬을 목록에서 빼므로, `config.toml`에서 꺼진 경로를 읽어 목록에 다시 넣는다. Codex 실행 파일로는
  `[[skills.config]]`의 `path`·`name`·`enabled`까지만 확인했고, `path`가 SKILL.md를 가리킨다는 점은 공식 문서를
  따랐다. 첫 적용 뒤 Codex 세션에서 그 스킬이 목록에서 빠지는지 확인한다.
- **ZCode 쓰기**: 이 PC에 `~/.zcode`가 없어 실제 파일 형식을 보지 못했다. 설정 폴더가 있을 때만 쓰고, 없으면
  보기 전용으로 둔다. 경로 키는 스킬 폴더로 썼다.
- **Qwen Code**: 세 목록은 범위끼리 합집합으로 합쳐지고, 워크스페이스의 `skills.enabled`는 신뢰한 폴더에서만 읽힌다
  (실행 파일에서 확인). 전역 자동은 두 목록에서 빼기만 하고, 프로젝트 예외 메뉴에 신뢰 폴더 안내를 붙였다.
- **주석 있는 JSON**: 읽기는 하지만 쓰지 않는다(다시 쓰면 주석이 사라진다). 화면에 이유를 보여 준다.
- **`skills on`**: 기준값이 값 하나라서 `on`은 자동이 된다(예전에는 `manualSkills`면 명시 전용으로 돌아갔다).
  명시 전용은 새 명령 `skills manual`로 정한다.
- **찾지 못한 에이전트**: 설정 폴더도 기록도 없는 에이전트(이 PC의 ZCode, Kimi Code)는 탭과 비교표에서 빼고 "이 PC에서
  찾지 못함" 한 줄로 알린다. 공유 폴더 `~/.agents/skills`만으로 목록이 생기는 것을 막기 위해서다.
- **정리 후보**: 호출 기록이 없는 에이전트(로그인 전 CodeBuddy, 기록 읽기 전인 Qwen)는 모든 스킬이 0회로 보이므로
  계산하지 않는다.
- **시안에서 고친 화면**: 선택 막대가 스크롤해도 위에 붙어 있다. 휴대폰에서는 요약 카드를 2×2 숫자로 줄인다.
  편집 범위 목록은 프로젝트별로 묶었다. 미리보기의 경로는 `~`로 줄인다. 변경 목록에 "마지막 적용 · 되돌리기"를
  늘 둔다. 현황판 링크로 들어오면 그 스킬 행으로 스크롤하고 초점을 옮긴다. 대기 중인 변경이 있으면 페이지를 떠날 때
  묻는다. "git 명령 복사"는 그 파일만 커밋하는 명령을 만든다.
- **남은 일 (4단계)**: Qwen Code·Kimi Code·ZCode 호출 기록 수집, 모델별 보기. Codex 프로젝트 예외는 시험 뒤에 켠다.
